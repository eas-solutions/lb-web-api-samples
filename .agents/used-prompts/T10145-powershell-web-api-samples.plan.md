## Plan: PowerShell Web API Samples

Move the whole `Powershell` tree to `Examples/Powershell`, then make every sample share one working-directory restore, one optional-parameter and session-variable rule, one JWT login, and one JSON writer. The client DLLs stay on protobuf. PowerShell serializes the .NET object the client already returned. Do not change the `lb-web` submodule and do not change `WebApiClient` to send or accept JSON.

**Steps**

1. From the repository root, create `Examples` and run `git mv Powershell Examples/Powershell`. Move the entire folder. That includes `Basics`, `ProjectsProposals`, `CompaniesAndPersons`, `ImportExport`, and `Scripts`, not only the scripts named in the original task list. After the move the tree contains `ImportAndLogin.ps1`, `Basics/100.LoadLoginInfos.ps1`, `ProjectsProposals/200.LoadProjects.ps1`, `ProjectsProposals/210.LoadProposals.ps1`, `CompaniesAndPersons/300.LoadCompany.ps1`, `310.LoadCompanies.ps1`, `350.CreateCompany.ps1`, `360.ModifyCompany.ps1`, `400.LoadPerson.ps1`, `410.LoadPersons.ps1`, `450.CreatePerson.ps1`, `460.ModifyPerson.ps1`, `ImportExport/410.ImportProposal.ps1`, `420.ExportProposal.ps1`, `430.ExportProject.ps1`, and `Scripts/ExecuteCustomScript.ps1`. Relative calls such as `..\ImportAndLogin.ps1` stay valid because only the `Powershell` folder moves.

2. Add `Examples/Powershell/Write-LbApiResult.ps1` as the only shared formatter. Every other script calls it with `&` and passes the response object. It writes `$global:LbApiOutput` to the original response object, then builds a serialization copy and stores `ConvertTo-Json -Depth 8` of that copy in `$global:LbApiOutputJSON`. Print with `Write-Host`, never `Write-Output`, so the JSON does not enter the pipeline. When `OperationResult.Successful` is true, print in the default console color. When it is false, print with `-ForegroundColor Red`. Do not add success or error text prefixes. On the serialization copy, replace each top-level `byte[]` property, including `ProposalFile`, with that array's `Length`. Leave the byte array on the original object in `$LbApiOutput`. A top-level list is any `IList` that is not a string and not a `byte[]`. A nested list is the `Value` property of a top-level object such as `Companies` or `Persons`. When such a list has more than 5 items, omit it from the pretty-printed object and then print each item with `ConvertTo-Json -Depth 8 -Compress` on its own line, in the same color as the pretty-printed object. Lists of 5 or fewer stay inside the pretty-printed object. This script also saves and restores the process location, as in step 3, even though it does not call `Set-Location`.

3. Apply the same location wrapper to every script, including `ImportAndLogin.ps1`, `Write-LbApiResult.ps1`, the import/export scripts, and `ExecuteCustomScript.ps1`. At the start, store `Get-Location`. Wrap the body in `try`/`finally`. In `finally`, call `Set-Location` back to the stored location when the current location differs. Use `return` to stop a script after a failed API call. Do not use `exit`, because `exit` inside a script started with `&` ends the PowerShell process. Duplicate this wrapper in each script. Do not add a second shared script for it.

4. Implement optional parameters with `$PSBoundParameters`. A key present in `$PSBoundParameters` is provided, and an explicit empty string is provided. Resolve each value in this order: if the parameter was provided, assign that value to the session variable; if it was omitted and the session variable exists, use the variable, including when the stored value is an empty string; if the variable does not exist, use that script's hardcoded fallback and assign it to the variable. Test existence with `Get-Variable -Scope Global -ErrorAction SilentlyContinue`, not with a truth check, so an empty string is distinct from an unset variable. `ImportAndLogin.ps1` owns the six connection values. Every other script declares the same six parameters and splats to `ImportAndLogin.ps1` only the connection parameters whose names are in that script's `$PSBoundParameters`. Other scripts do not resolve connection fallbacks themselves and do not log in.

5. Rewrite `Examples/Powershell/ImportAndLogin.ps1`. Remove the relative loads of `..\lb-web\Bin\Client\EAS.DataTransfer.dll`, `EAS.LeegooBuilder.Web.WebApiClient.dll`, and `EAS.LeegooBuilder.Common.DataTransferObjects.dll`. Remove any `C:\Quelltexte\...` path and the `D:\WebAPI\Client` path. `DllPath` is one directory. Load these three files from that directory, in this order: `EAS.DataTransfer.dll`, `EAS.LeegooBuilder.Web.WebApiClient.dll` with `-IgnoreWarnings`, and `EAS.LeegooBuilder.Common.DataTransferObjects.dll` with `-IgnoreWarnings`. Call `Add-Type` for a DLL only when `AppDomain.CurrentDomain.GetAssemblies()` does not already contain that assembly's simple name, so a later call in the same session does not fail. When `ApiUrl`, `Username`, or `Password` is present in `$PSBoundParameters`, set `$LbAccessToken` to `$null` before the token check. `Culture`, `Language`, and `DllPath` do not clear the token. When `$LbAccessToken` is set, construct `EAS.LeegooBuilder.Web.WebApiClient.WebApiClient` with `(Uri, string)` using that token and call `IsAccessValid()`. When that returns true, keep the client and do not call `LoginAsync`. When the token variable is missing or `IsAccessValid()` is false, construct the client with the URI only, build `EAS.LeegooBuilder.Web.Contracts.Models.ParameterClasses.Authentication.LoginParameter` from the resolved username, password, culture, and language, and call `AuthenticationClient.LoginAsync(...).GetAwaiter().GetResult()`. On success, store `User.Token` in `$LbAccessToken`. On failure, set `$LbAccessToken` to `$null`. A direct run is an empty `$MyInvocation.ScriptName`. On a direct success, call `Write-LbApiResult.ps1` with the login result and do not write the client to the pipeline. On a nested success, write only the client to the pipeline and do not call `Write-LbApiResult.ps1`, do not set `$LbApiOutput` or `$LbApiOutputJSON`, and do not print the login result. On a failed login, whether direct or nested, call `Write-LbApiResult.ps1` so the failed result is stored and printed in red, then throw `OperationResult.ShortMessage` so the caller stops. Remove the `Write-Debug` login text.
